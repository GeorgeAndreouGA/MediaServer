# Static IP Configuration

> **Goal:** give the server a fixed, predictable address on the LAN so services, port forwards, and DNS records never break because the IP changed.

This setup has **two parts, and both are required**:

1. **DHCP reservation** on the router — binds the IP to the device's MAC address centrally.
2. **Static IP on the device itself** — makes the OS aware of its own fixed address (needed for NetworkManager-based configuration and for setting DNS servers).

---

## Step 1 — DHCP Reservation (Router-Side)

This is the primary, recommended method. Setting a static IP only on the device (without a matching router reservation) risks "floating IP" conflicts if the router hands the same address to another device.

### Why this approach is preferred

| Benefit                   | Explanation                                                                                         |
| ------------------------- | --------------------------------------------------------------------------------------------------- |
| Centralized management    | The router controls all IP assignments, making it easy to manage multiple devices                   |
| No IP conflicts           | The router won't hand out an address that's already reserved                                        |
| Easy to change later      | Reassign IPs from the router without touching the device                                            |
| OS-independent            | Works even if you reinstall the OS or change network settings — the device always gets the same IP |
| Less manual configuration | Reduces the chance of human error                                                                   |
| Still DHCP-compliant      | The device still uses DHCP; the "static" behavior is handled centrally by the router                |

### Steps

1. Log into your router's admin panel.
2. Find the DHCP reservation feature — usually labeled **DHCP Reservation**, **Static Leases**, or **Address Reservation**.
3. Identify the device's MAC address:
   ```bash
   ip link
   ```

   Look for `eth0` (wired) or `wlan0` (Wi-Fi), or find it in the router's connected-devices list.
4. Create a DHCP reservation, assigning a fixed IP (within your LAN range) to that MAC address.
5. Save and apply the changes on the router.
6. On the device, apply the change:
   ```bash
   sudo systemctl restart networking
   # or, to be safe, reboot fully (unplug/replug, or):
   sudo reboot
   ```
7. Verify the assigned address:
   ```bash
   ip a
   ```

---

## Step 2 — Static IP on the Device (NetworkManager)

Setting the IP on the device too means you can refer to it by IP instead of tracking down its MAC address. This helps when a server moves to another network.

> Confirm which network manager your distro uses before following this section. The steps below are for **NetworkManager**, the default on most Raspberry Pi OS / Debian-based systems.

> **This breaks automatic hostname resolution.** A device getting its IP through DHCP — including the reservation in Step 1 — sends its hostname along with the request (DHCP option 12). Routers and managed switches that watch DHCP traffic use that to resolve/display the device by name on the LAN, with zero configuration on your end. Configuring the IP statically here bypasses DHCP entirely, so that hostname is never sent — nothing on the network learns it automatically anymore. Step 1 alone (DHCP reservation) does **not** cause this, since the device still completes a full DHCP handshake; it's specifically this step, setting the IP directly on the device, that does.
>
> If you still want to reach the server by name after this, add the mapping yourself in your local DNS (e.g. Pi-hole): an `A` record if it's a new name, or a `CNAME` if it's an alias to a name that already has one — see [DNS layers: Cloudflare vs. local DNS](<../nginx and cloudflare configurations/5. setting a domain name with ssl cert.md>) for the `A`-vs-`CNAME` rule.

1. Find the connection name:

   ```bash
   nmcli connection show
   ```

   e.g. `Wired connection 1`
2. Set a static IPv4 configuration:

   ```bash
   sudo nmcli connection modify "<connection-name>" \
     ipv4.method manual \
     ipv4.addresses <static-private-ip>/<prefix> \
     ipv4.gateway <default-gateway> \
     ipv4.dns "<primary-dns> <secondary-dns>"
   ```
3. Reboot:

   ```bash
   sudo reboot
   ```
4. Confirm the change applied:

   ```bash
   nmcli connection show "<connection-name>" | grep ipv4
   ```

### DNS configuration guidance

| Role                                      | `ipv4.dns` primary                 | `ipv4.dns` secondary |
| ----------------------------------------- | ------------------------------------ | ---------------------- |
| Server acting as local DNS (e.g. Pi-hole) | `8.8.8.8`                          | `8.8.4.4`            |
| Server**not** acting as local DNS   | `<private-ip-of-local-dns-server>` | optional               |
| Client devices                            | `<private-ip-of-local-dns-server>` | optional               |

Only point a client's primary DNS at the server's private IP if that server is running a local resolver (e.g. Pi-hole).

---

**Both Step 1 and Step 2 must be applied.**
