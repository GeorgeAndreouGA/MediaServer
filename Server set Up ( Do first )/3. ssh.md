# SSH Hardening

## 1. Install and enable SSH

```bash
sudo apt install ssh
sudo systemctl start ssh
sudo systemctl enable ssh
```

You can now SSH in using the regular (non-SFTP-only) user — the first user created during OS installation, per [SFTP setup](<2. sftp.md>).

## 2. Disable root login

In `/etc/ssh/sshd_config`:

```
PermitRootLogin no
PasswordAuthentication yes
```

## 3. Connect

```bash
ssh <regular-user>@<static-ip>
```

---

## Defense in depth: three independent layers

Beyond disabling root login, harden SSH access with three complementary controls. Each is independent — if one is misconfigured, the others still hold.

### Layer 1 — `AllowUsers` in `sshd_config`

> **Ordering matters:** `AllowUsers` must appear **before** the `Match User <sftpuser> ...` block from [SFTP setup](<2. sftp.md>).

```
AllowUsers <username>@<private_ip>
```

Restricts which source IPs are permitted to authenticate as which user.

### Layer 2 — Firewall (UFW)

See [Firewall (UFW)](<4. ufw ( firewall ).md>) for the full configuration.

### Layer 3 — PAM (`pam_access`)

In `/etc/ssh/sshd_config`:

```
UsePAM yes
```

In `/etc/security/access.conf`:

```
+ : <username> : <private_ip>[ <private_ip> ...]
- : ALL : ALL
```

> The `- : ALL : ALL` deny-all rule must be the **last** line, after every allow rule above it.

In `/etc/pam.d/sshd`:

```
account required pam_access.so
```

In `/etc/pam.d/login`:

```
account required pam_access.so
```

Apply the changes:

```bash
sudo systemctl restart ssh
```
