# VPN Setup (Tailscale Exit Node)

> **Goal:** securely reach every service on the home network from anywhere, with the server acting as a Tailscale **exit node** — once connected, all client traffic routes through the server rather than through whatever network the client is on.

## 1. Install Tailscale on the server

1. Create a Tailscale account.
2. Add the server to your Tailscale account, selecting **Linux** as the OS.
3. Run the install command it gives you on the server.
4. In the Tailscale admin console, disable **key expiry** for the server (repeat this for each client later too).
5. Under **Settings → Device management**, enable **Device approval**.

## 2. Enable IP forwarding on the server

The server needs to forward traffic on behalf of connected clients.

If `/etc/sysctl.d` exists:
```bash
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl -p /etc/sysctl.d/99-tailscale.conf
```

Otherwise:
```bash
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p /etc/sysctl.conf
```

## 3. UFW configuration for forwarding

Allow forwarded traffic:
```bash
sudo nano /etc/default/ufw
```
Change:
```
DEFAULT_FORWARD_POLICY="DROP"
```
to:
```
DEFAULT_FORWARD_POLICY="ACCEPT"
```

Edit `/etc/ufw/before.rules`. At the **top**, before the `*filter` rules, add:
```
*nat
:POSTROUTING ACCEPT [0:0]
-A POSTROUTING -s 100.64.0.0/10 -o <network-interface> -j MASQUERADE
COMMIT
```
> `100.64.0.0/10` is Tailscale's CGNAT address range — don't change it.

After the `*filter` rules in the same file, add:
```
-A FORWARD -i tailscale0 -o <network-interface> -j ACCEPT
-A FORWARD -i eth0 -o tailscale0 -m state --state RELATED,ESTABLISHED -j ACCEPT
```

Verify NAT is active:
```bash
sudo iptables -t nat -L -n -v
```
You should see a line like:
```
0     0 MASQUERADE  0    --  *      eth0    100.64.0.0/10        0.0.0.0/0
```

Allow Tailscale clients through to specific services — by the whole CGNAT range or a single Tailscale IP (give the client and server static Tailscale IPs for this to be reliable):
```bash
sudo ufw allow from 100.64.0.0/10 to any port <service-port> proto <protocol>
sudo ufw reload
```

## 4. UDP GRO forwarding (performance tuning)

```bash
sudo ethtool -K <network-interface> rx-udp-gro-forwarding on rx-gro-list off
```

Find the active NetworkManager connection name:
```bash
nmcli -t -f NAME,DEVICE connection show --active
```

Apply persistently:
```bash
sudo nmcli connection modify "<connection-name>" ethtool.feature-rx-udp-gro-forwarding on
sudo nmcli connection modify "<connection-name>" ethtool.feature-rx-gro-list off
sudo nmcli connection down "<connection-name>" && sudo nmcli connection up "<connection-name>"
```

Verify:
```bash
nmcli connection show "<connection-name>" | grep ethtool
ethtool -k eth0 | grep -E "udp-gro-forwarding|gro-list"
```

Restart Tailscale and confirm status:
```bash
sudo systemctl restart tailscaled
tailscale status
```

**IP forwarding is now fully enabled.**

## 5. Advertise the exit node and subnet route

```bash
tailscale up --advertise-exit-node --advertise-routes=<server-subnet, e.g. 192.168.10.0/24>
```

In the Tailscale admin console, approve both the exit-node and subnet-route settings for this device.

> You may see a warning that the exit node isn't fully enabled — this is expected. It only refers to IPv6, which isn't needed here.

In your nginx configs, allow the `100.64.0.0/10` range (or the specific Tailscale IP) for every service that VPN clients need to reach.

## 6. Client setup

1. Install Tailscale on the client.
2. Log in and approve the device in the admin console.
3. Select the Linux server as the **exit node**.

## 7. Split DNS (Tailscale MagicDNS)

> Only relevant if the server also runs a local DNS resolver (e.g. Pi-hole).

In the Tailscale admin console, under **DNS → Nameservers**:
1. Remove every nameserver except MagicDNS.
2. Click **Add nameserver → Custom** and enter the server's Tailscale IP.
3. Enable **only** "Restrict DNS (split DNS)" and add the domain(s) that should resolve through it.
4. Leave **"Use with exit node"** disabled.

On the local DNS server itself (not Tailscale), allow DNS on **both** the LAN and Tailscale interfaces — `53/udp` and `53/tcp`. See the Pi-hole service documentation (`Services/pi-hole ( docker )/installation.md`) for the container-level config.

## 8. Cleanup

Disable **Tailscale SSH** in the admin console — it's redundant, since SSH is already reachable on port 22 (see [SSH Hardening](<3. ssh.md>)).
